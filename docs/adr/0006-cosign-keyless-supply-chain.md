# ADR-0006: Sigstore Cosign Keyless Signing & Digest Pinning

## Status
**Accepted** (2026-04-01)

## Context
Container supply chain attacks, tag manipulation (mutability of `:latest` and semver tags), and compromised upstream base images pose severe security risks to enterprise automated code review systems.

## Decision
We adopted a multi-layered cryptographic supply-chain security model:
1. **Immutable SHA-256 Digest Pinning:** All base images in `Dockerfile` and all container images in `k8s/` manifests are pinned to immutable `sha256:...` digests. A dedicated script (`scripts/validate_k8s_image_pinning.py`) enforces this in CI.
2. **Deterministic Dependency Hashes:** Dependencies in `requirements.txt` are compiled into `requirements-lock.txt` with strict SHA-256 hashes generated by `pip-compile --generate-hashes`. Container builds run with `pip install --require-hashes`.
3. **Keyless Signing via Sigstore Cosign:** Production release images are signed using OpenID Connect (OIDC) identity tokens via GitHub Actions and Fulcio transparency log (Rekor).
4. **CycloneDX SBOM & SLSA Attestation:** CycloneDX SBOMs and SLSA build provenance attestations are cryptographically attached to every release image.

## Consequences
### Positive
- Guarantees that only authentic, untampered images built directly by the official release workflow can be deployed into production clusters.
- Eliminates long-lived signing keys that can leak or require rotation.
- Fulfills Executive Order 14028 and OpenSSF supply chain security criteria.

### Negative
- Local developers building ad-hoc images cannot sign without OIDC identity tokens, so signing verification is restricted to production deployments.
